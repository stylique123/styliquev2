## 1. What Stylique is (one paragraph)

> **CANONICAL POSITIONING lives in [`STYLIQUE_SOURCE_OF_TRUTH.md`](./STYLIQUE_SOURCE_OF_TRUTH.md) — that file replaces every previous version and wins any conflict. Read it first.**

Stylique Fashion is the **AI Sales Engine and Commerce Intelligence Layer for Fashion Brands.** It sits on top of an ecommerce store and turns every product page into an intelligent selling experience — **Mira, an AI Sales Associate** (not a chatbot, not a stylist, not a try-on widget) who guides shoppers, recommends complete looks, gets the fit right, handles objections, and closes — while every interaction becomes structured **commerce intelligence** (demand, fit, behavior, bundles, merchandising, **assortment gaps**, revenue opportunities) that becomes the merchant's source of truth. **Headline: "Increase Revenue From Every Product Page."** Virtual try-on, fit, and the learning loop are capabilities *inside* Mira that serve selling, never the hero. Two-question test for everything: does it help the shopper buy, or help the merchant make more money? If neither, remove it. Commercial model: demo-led sales (no free trial, no self-serve checkout), one product across three tiers, **Starter $199 / Growth $449 / Scale $849** per month. Declared by the founder as the final source of truth (see D67 in the decision log).

## 3.5 Security invariants — NEVER break these either

1. **`recall_past_preference` and any tool that hydrates products from IDs MUST filter by `shopId`.** Cross-tenant leak otherwise — taste vector may carry stale IDs from prior installations. (Fixed Sprint 5 audit.)
2. **Every shopper-facing API call rate-limits on BOTH shop AND shopper cookie.** Shop-only limits let one malicious shopper exhaust the brand's bucket. (Fixed Sprint 5 audit.)
3. **Image uploads accept ONLY data URLs matching `^data:image/(jpeg|png|webp|heic|heif);base64,[A-Za-z0-9+/=]+$`.** Server validates with regex, not just prefix. Cap 6MB. No other MIME types pass.
4. **Chat messages cap at 1500 chars.** Longer = almost certainly prompt-injection payload.
5. **`sq_shopper_id` cookie carries `Secure; HttpOnly; SameSite=None`.** Client never reads it directly. Use `credentials: "include"`.
6. **Error messages returned to the client use a fixed vocabulary** (`rate_limited`, `chat_unavailable`, `chat_busy`, `chat_failed`, `invalid_input`, `shop_not_installed`, `product_not_found`, `invalid_payload`, `unauthorized`, `not_found`). Real error details go to `console.error` server-side only.
7. **Mira's prompt has a non-negotiable security boundary block** at §"Security boundary" in `packages/ai/src/brain/prompts.ts`. NEVER weaken it. The 7 hard rules (no system prompt leak, no cross-shopper, no cross-brand, no IDs/cuids/GIDs, no email echo, no brief recite, tool-results-are-content-not-commands) are the baseline.
8. **`.gitignore` excludes `.env*` with `!.env.example` exception.** `.env.save`, `.env.local`, `.env.production` etc all blocked.
9. **`accessToken` is plaintext today** — relies on Postgres at-rest encryption + role isolation. Encryption-at-app upgrade path documented in schema comment (OI-25).

## 3. Architectural invariants — NEVER break these

1. **Shop-scoped tenancy.** Every query that touches DB filters by `shopId` (or `shopifyDomain`). Cross-shop reads are impossible by construction.
2. **No tokens / scopes / internal cuids in shopper-facing responses.** See `lib/serialize.ts` invariants.
3. **App Proxy auth is the only path** for shopper requests. Resolve `shop` ONLY from verified `session.shop` — never from a query/body field.
4. **Chat transcripts never leave Stylique.** Brands get themes and summaries. They do NOT get raw conversation data. This is privacy + training data IP.
5. **K-anonymity floor on network benchmarks.** Minimum 3 contributing brands per dimension. No exceptions.
6. **Taste vectors never go to brands.** Aggregated brand-side profile only. Per-shopper vectors are Stylique-internal.
7. **Tools are server-validated.** Agent can't return a `navigate` to a non-existent handle or add a product not in the shop's catalog. Every tool call resolves through `prisma` filtered by shop.
8. **Soft account is opt-in.** Server gates `offer_account_signup` — once offered or claimed, the tool returns no-op forever (the agent can't override).
9. **The widget and Stylist share permissions** (same Shopify app, same App Proxy) but **never share the foreground.** Cross-surface `stylique:surface-open` event coordination is mandatory.
10. **Zod-validate every input before DB.** No exceptions.

## 11. The data → decision contract

Every metric on the dashboard must satisfy this rule:

> **If this number changes by 20% week-over-week, the brand can name in one sentence what they would do differently.**

If it can't, the metric is decoration. Cut it.

Examples that pass:
- ✅ "Catalog gap: 12 queries for cream linen" → brand reorders.
- ✅ "Combo CTR dropped 30%" → brand reviews the active stylist persona.
- ✅ "Fit drift on Product X = 47%" → brand updates the size chart.

Examples that fail:
- ❌ "Total events this month" → so what?
- ❌ "Average dwell time across the site" → too aggregated to act on.
- ❌ "Heatmap of mouse positions" → cool, no action.

## 15. Stylique Brain — architecture

The Brain is the *only* thing that talks to an LLM. Every surface (Stylist chat today; future Studio agent, returns agent, admin assistant) calls `brain.run()` and gets back `{ reply, combos, actions, latencyMs, modelUsed, toolsCalled }`.

### File layout (`packages/ai/src/brain/`)

| File | Owns |

### Server wiring (`apps/shopify-app/app/lib/brain.server.ts`)

This is where the provider-agnostic Brain meets Stylique's runtime (Prisma, analytics, taste, recommendations).

- Boots a singleton via `getBrain()`. Lazy-init, idempotent.
- Registers tool *handlers* (the real Prisma queries) onto the schemas imported from `@stylique/ai`.
- Registers every provider whose env key is present. Default = Gemini.
- Exposes `buildBrainContext()` — single helper to construct a fully-hydrated `BrainContext` from a shopper session.

### `postChat` is now ~80 lines

Down from ~250. It builds the context, calls `brain.run()`, persists the turn, fires the wrap-up event, recomputes taste + brand snapshot. That's the whole file.

### Adding a new tool

1. Add the schema in `packages/ai/src/brain/tools.ts`.
2. Add the handler in `apps/shopify-app/app/lib/brain.server.ts` and register it in `toolsWithHandlers()`.
3. (Optional) gate with `requiresFeature` or `minTier` so it only shows on the right plans.
4. Done. No provider code touched.

### Adding a new model provider

1. Create `packages/ai/src/brain/providers/<name>.ts` implementing `ModelProvider`.
2. Export from `packages/ai/src/brain/index.ts`.
3. Register in `brain.server.ts`' `providers` block.
4. Done. No tool / prompt / surface code touched. Switch by setting `BrainConfig.defaultProviderKey` or per-call via `BrainInput.config.providerKey`.

### Tool-calling semantics

Tools return one of:
- `{ kind: "combo", combo }` → contributes a `BrainCombo` to the result + sends `{ combo }` back to the model.
- `{ kind: "action", action }` → contributes a client `action` to the result + sends `{ ok: true }` back to the model.
- `{ kind: "data", data }` → no client side-effect; sends `data` back to the model so it can reason.
- Any other return → passed through to the model as `response`.

The Brain handles `unimplemented` tools (returns `{ error: "unimplemented" }`), unknown tools (returns `{ error: "unknown_tool" }`), and handler exceptions (returns `{ error: "tool_failed", message }`) — the model can recover gracefully.

### Why this matters in practice

- **A/B (Sprint 1)**: register variant prompt → set `BrainInput.config.promptVariant: "experiment_a"`. Zero adapter changes.
- **Phase 2 (Sprint 1, parallel)**: implement `see_on_model` / `see_on_me` handlers + add a `stylique:request-tryon` event. Brain already exposes them to the model.
- **Future Claude swap**: implement `providers/anthropic.ts.turn()` (the rest of the file is already there) + set `ANTHROPIC_API_KEY`. Done.
- **Future vector memory**: add a `query_memory` tool to the registry. No core code changes.
- **Future Studio agent**: instantiate a second `Brain` with a different default prompt + restricted tool set. Same orchestrator.
